# 2026-11-16：转弯被航向判据拒绝的地面车辆修复

## 实测入口与根因

ROS2实机转弯请求已收到协议ACK，但vgsolar_event显示accepted=False、reason=6，未进入吸盘序列。此前reason=1是未解锁，需与本问题分开。

会话最新输入模块、清洁使能及Servo 1映射已逐步接入；vehicle_local_position.heading_good_for_control仍为False。log155中cs_yaw_align=1、cs_mag_hdg=1、cs_mag_fault=0、cs_mag_field_disturbed=0，而cs_mag_aligned_in_flight一直为0。

EKF2的heading_good_for_control来自isYawFinalAlignComplete()。使用磁航向时，该判据要求飞行中的最终磁对准；mag_control.cpp将地面磁异常高度区间外的重置用于飞行对准。VGSolar的地面转弯直接复用了这个字段，可能在磁航向已对准且无故障时仍持续拒绝。不能把heading字段有数字等同于有效，也不应简单删除航向检查。

## 本次改动

仅修改VGSolar转弯入口和运行中的航向有效性检查：

1. 本地位置消息须新鲜（不超过500 ms）、不是未来时间，heading须有限。
2. 原生heading_good_for_control为True时，沿用原行为。
3. 原生字段为False时，只对vehicle_type=ROVER提供地面磁航向路径。航向估计器须报告yaw_align，且正在融合磁航向或3D磁场，无磁故障或磁场干扰。
4. 多EKF依据estimator_selector_status选择对应的estimator_status_flags实例；选择器及状态标志最多允许2秒。EKF2的PublishStatusFlags正常约1 Hz、状态变化时立即发布，因此不能套用高频本地航向的500 ms限值。没有有效选择器时，SENS_IMU_MODE=0的多EKF配置拒绝，不错误复用实例0。本地航向本身仍要求500 ms以内。
5. 转弯执行过程中仍连续检查，heading_reset_counter变化、速度反馈无效、磁故障、陈旧数据仍按原有停止/抬升路径处理。
6. 事件reason=9用于航向判据拒绝，减少此前reason=6的模糊性。未解锁仍reason=1，不将接收ACK当执行成功。

没有修改EKF本身、解锁检查、压力/红外条件、吸盘状态机、负压阈值、泵阀引脚或PWM端点。位置导航和全局导航的原有heading_good_for_control要求未放宽。

当前升降配置已改：MAIN3=201（Servo 1），1000～2000、center1500；PWM_MAIN_REV=1保留左行走反向，抬起端点VGS_SC_PWM_R=1881。SD独立备份lift_1116.bson已完整解码1882字节。原先41字符的备份文件名超过FAT40字符限制，未成为有效旧配置备份。

舵机1881抬起已由用户确认；下降端点1100、实际红外下到位及-70 kPa负压联动尚未完成本轮完整验收。准备修复固件不等于已验证完整机构行程。气路未密封时不应通过降低负压要求或关闭传感器检查强行转弯。

默认转弯请求是按真实机体航向完成。车架完全固定时，履带空转不会产生10度实际机体偏航，不能据此认定角度转弯通过；应预期保持检查并按超时/故障撤销运动。启动、取消和故障回收都须记录ULog并观察实物。

本修复不改变参数默认值；实机升降映射及完整转弯验收状态见 [11月16日实测](validation_20261116.md)。

## V8：纠正V7状态标志发布频率假设

V7刷写后用户回读estimator_status_flags为约0.93秒前，暴露V7使用500 ms时效门限过紧；我先前的宿主模型每20 ms重发标志，未覆盖真实1 Hz发布。V8将状态标志门限改为2秒，新增按1 Hz发布且连续维持转弯的生产状态机回归，并验证0.93秒健康标志可用、超过2秒仍拒绝。该改动不影响高频航向、速度、输入数据的原有时效检查。
